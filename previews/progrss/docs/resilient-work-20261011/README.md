## Recovery boundary

All required files for understanding and continuing this design are listed in MANIFEST.json and are adjacent to this README. No private-only artifact is required to recover the design bundle. Earlier project commits, audit files and incident records mentioned by individual documents are provenance for historical claims; this bundle does not repeat those historical audits or supply a complete application checkpoint. Access to those additional artifacts is required before rechecking their underlying evidence or restoring the application.

The detailed incident report and raw operational appendix are preserved separately. Their absence from this shareable design bundle does not mean the application archive, original uploads or incident evidence are replicated here. Technical reports, exact source custody, implementation acceptance and live deployment remain separate outcomes.

## Continue from here

1. Read the integrated design and the independent review, then confirm the current authorized scope and actual available execution and publication tools.
2. Select one bounded implementation item. Start with one useful direct-file result, its job card and resume step, a shared manifest, independent destination intents, exact readback and fresh-directory recovery. Do not begin with a scheduler or a large archive migration.
3. Before using old project code, retrieve its required closure from an authorized immutable source, verify bytes, and separately establish safe materialization and execution eligibility.
4. Record exact candidate identity, ownership, acceptance checks, next useful result and stopping condition. Keep every proposed fault scenario labeled untested until it is actually exercised.
5. Preserve useful bounded results promptly through independently guarded eligible destinations. Reconcile an uncertain write before retrying; keep replication debt separate from first-copy custody.

This record creates no workers, schedule, service, credential, repository permission or deployment change. Existing STATUS and QUEUE files are not changed by its preservation.
